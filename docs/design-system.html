VSIX Tool Window
Design System

One visual language for every WebView2-hosted tool window docked in TwinCAT XAE Shell. The tokens are lifted verbatim from the shipping TcAgent chat panel — this document codifies them and adds the result-tree layer that TcXunit needs, so both panels read as one product sitting in the same sidebar.

Foundations — Color

Two themes, one token set

Every surface, border, and text color comes from a custom property. Components never name a hex value. Theming is one block of redefinitions on body[data-theme="light"], which is what lets the panel follow the shell's theme without touching component CSS.

Extension: result status

TcXunit needs a pass/fail/skip vocabulary. Rather than introduce hues, it aliases the ones already in the system — so a green check in the test tree is literally the same green as the "Local" segment in TcAgent. Aliasing, not addition, is how this system grows.

AliasResolves toEncodes
--passvar(--local)Assertion held. Glyph ✓, 20% wash.
--failvar(--error)Assertion failed or suite threw. Glyph ✗, 12% wash + border.
--skipvar(--text-faint)Not run. Deliberately colorless — absence is not a warning.
--busyvar(--accent)In flight. Same blue as every other "the tool is working" signal.
Foundations — Type

Segoe UI at IDE density

Two faces only. Segoe UI for all interface text — it is the shell's own face, so the panel doesn't announce itself as a web view. Consolas for anything the user could paste into an editor: paths, identifiers, assertion output, durations. Sizes run 9.5–12.5px. That is not small for the web; it is correct for a docked tool window sharing a screen with Solution Explorer.

Components — Results layer

The test tree

New components, built only from tokens above. The tree is the whole product for TcXunit, so it gets the density budget: status is encoded in glyph and color, the source file rides along at 10.5px mono because double-click opens it, and duration right-aligns in tabular figures so slow tests are findable by scanning one column.

Pattern

Tool window anatomy

Every panel stacks the same regions. Only the middle one is optional in shape; the edges are fixed.

/* top to bottom — flex column, height:100vh, overflow:hidden */
.tw-tabs       flex:none   chrome-bg-2   optional — only with 2+ views
.toolbar       flex:none   chrome-bg-2   primary action left, counts right
.prog          flex:none   2px           only while work is in flight
.tw-body       flex:1      panel-bg      min-height:0 — the scroll region
.tw-inputwrap  flex:none   chrome-bg-2   optional — input-driven panels only
.tw-ctrlbar    flex:none   chrome-bg-2   optional — persistent settings
.tw-statusbar  flex:none   20px #007acc  required — never omitted
Always

min-height:0 on the scroll region. Without it the flex child refuses to shrink and the status bar gets pushed off the bottom of the panel.

Always

One primary action per panel, leftmost in the toolbar. Counts and status push right with margin-left:auto.

Never

Horizontal body scroll. Long paths truncate with ellipsis; code and tables get their own overflow-x:auto container.

Never

A second elevation level. If it isn't a popover, it doesn't get a shadow. Separation is done with borders.

Rules

How to extend this without breaking it

Do

Alias before adding. A new semantic gets a token that resolves to an existing hue. Two panels drift the moment one of them invents a green.

Do

Encode state twice. Color plus shape — glyph, pill fill, left rail. Contrast on a projector, or a colorblind reviewer, must still read pass from fail.

Do

Style through tokens. Components reference custom properties only; the light theme stays a single block of redefinitions.

Do

Make the click target look clickable. Rows that navigate reveal the ↗ on hover. Rows that don't, don't.

Don't

Write a hex in a component rule. The only literal colors in the system are #fff on filled buttons and the status bar's own text.

Don't

Scale up for comfort. 12px rows are correct here. A panel that out-sizes Solution Explorer next to it reads as a foreign object.

Don't

Animate layout. Opacity reveals at 0.1s are the ceiling. Motion in a docked panel is noise in someone's peripheral vision.

Don't

Use emoji as status. They render inconsistently in WebView2 across Windows versions and break the density budget. Glyphs and hues only.

Implementation

Sharing the sheet between panels

The tokens and core components want to live in one file both VSIX projects embed; each panel adds only its own layer. TcXunit's layer is the results tree — nothing else. 

Resources/
  vsix-tokens.css     :root + body[data-theme="light"] — shared, never forked
  vsix-shell.css      tabs, buttons, seg, field, chip, picker, statusbar
  results.css         TcXunit only: .toolbar .tree .node .assert .banner .count
  chat.css            TcAgent only: .msg-* .md-content .tw-inputbox

// theme follows the shell, set once from the host
document.body.dataset.theme = hostIsLightTheme ? "light" : "dark";
Host

Theme comes from VS, not from prefers-color-scheme. WebView2 does not inherit the shell's theme — the host pushes it in and re-pushes on theme change.

Data

Tree rows bind to the CLI's JSON: suites[].name, suites[].filePath, suites[].error, suites[].tests[]. filePath is what ItemOperations.OpenFile receives on double-click.

Fonts

No web fonts. Segoe UI and Consolas are already on every machine running XAE Shell. A CDN request from a WebView2 panel is a support ticket waiting to happen.

A11y

Keyboard parity: arrow keys move selection, Enter opens the file, Space toggles the twisty. Focus gets a visible --accent outline everywhere.
